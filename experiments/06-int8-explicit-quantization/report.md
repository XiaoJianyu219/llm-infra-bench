# Day 06 — INT8 显式量化与输入尺寸对照

## 1. 结论

- **原来的长宽比解释不成立。** 当前评测集图片全部为正方形；真实张量核验表明输入策略改变后，
  有效图像四边各增加了少量灰边，抽查中心像素差为 0。来源：本目录results的划分记录
- **同一评测集上，mAP50-95 增加 0.03965。** 固定尺寸与动态尺寸两种引擎的结果几乎相同
  （差 0.00004）；固定形状也能复现收益；动态能力本身不是这次精度收益的必要条件。
  证据：`metrics_pytorch.json`、`metrics_pytorch_rect.json`、`metrics_fixed1056.json`、
  `metrics_dynamic1056.json`。
- **动态代价由同尺寸对照衡量。** 同一尺寸下动态相对固定引擎的中位延迟变化为 -2.45%
  （固定 2.600 ms,动态 2.536 ms）。证据：`latency_paired.json`。
- **INT8 最终候选:排除输出头。** mAP50-95 与 FP32 相当、mAP50 略低,中位延迟 1.694 ms。
  80 张样本上出现 0 次类别翻转,但不代表全量零风险。证据:`metrics_int8_head_excluded.json`、
  `alignment_summary.json`、`latency_paired.json`。
- **精度提升伴随虚警变化。** 换成带灰边的输入后,背景图上的误检框数几乎翻倍;
  INT8 候选的误检数最低,但有 282/1518 个参考高分候选跌破阈值,mAP50、召回和概率分布均有变化。
  **更低虚警不等于整体无损。**

## 2. 数据与方法

**评测口径变化,不是性能变化。** 本报告所有精度差值只在同一评测集内计算;不把上一日
更大评测集的结果与本次结果直接相减。

划分:固定随机种子,按文件名前缀分层抽样,校准集与评测集清单交集为 0;
图片内容哈希去重检查未发现跨校准/评测边界的重复。来源:`split_summary.json`。

数据集用硬链接组织,标签路径保持 `/images/` → `/labels/` 映射规则,创建或改变数据集后删除缓存。
静态预处理为 `LetterBox(1024, auto=False, scaleup=True)`、BGR→RGB、CHW、float32/255,
与默认验证器抽查逐像素一致。带灰边的输入采用在有效图像四边各补相同宽度,
不使用直接放大到目标尺寸的 LetterBox。证据:`preflight.json`、`preprocessing_check.json`、
`rect_preprocessing_check.json`。

Python、CUDA、TensorRT 与 ultralytics 版本的实际值及 API 核验见 `preflight.json`、
`inspect.log`;GPU 见 `gpu.csv`。未升级安装包。模型等价简化每次都强制检查返回值。

## 3. 评测集精度(相对基线)

下列数值均为相对同一评测集 PyTorch 1024 基线的差值,不列绝对水平:

| 档位 | mAP50-95 相对基线 | mAP50 相对基线 |
|------|------------------|----------------|
| PyTorch 1024 | 基线 | 基线 |
| TRT FP32 1024 | -0.00006 | +0.00010 |
| TRT FP16 1024 | **-0.00447** | +0.00032 |
| INT8 全量 QDQ | 归零(见第 4 节) | 归零 |
| INT8 排除输出头 | **+0.00328** | **-0.00337** |
| PyTorch 带灰边输入 | **+0.03965** | **+0.04704** |
| TRT 固定 FP32(灰边) | +0.03930 | +0.04715 |
| TRT 动态 FP32(灰边) | +0.03926 | +0.04712 |
| TRT 动态 FP32 @1024 | -0.00016 | +0.00001 |

两条读数纪律:静态 FP16 的下降是**数值精度档位对照**;带灰边输入的提升**同时包含输入形状改变**,
二者不是相同机制,不能并列比较。INT8 候选的 mAP50-95 高于 FP32 基线,但 mAP50 更低、
且伴随阈值附近候选的移动,**不能读成"INT8 更准"**。

### 动态形状的边界

profile 的 min/opt/max 分别采用实测的两种输入模式(1024/1056/1056),batch 固定为 1。
实际验证的尺寸只有这两种;不宣称覆盖其他长宽比分布或 profile 内所有中间尺寸。
固定与动态使用同一导出流程及 FP32,作为主要动态开销对照。旧固定 1024 的导出图与本次
新导出图不同,因此它与动态 1024 的延迟差不能完全归因于动态机制。
来源:`dynamic_profile.json`、`dynamic_build.json`。

中心图像像素相同,排除了"有效目标像素被放大"的解释。额外灰边、输入边界位置及特征网格
响应的具体贡献尚未分离,本报告不做未经验证的机制归因。

## 4. INT8 方法、失败与排除

使用 `onnxruntime.quantization.quantize_static`,QDQ、`per_channel=True`、对称 QInt8
权重和激活、MinMax,固定校准集,bias 保持浮点,`DedicatedQDQPair=True`;
通过 `STRONGLY_TYPED` 构建 TensorRT 引擎,没有使用 TensorRT 隐式 calibrator 或已移除的
INT8/FP16 builder flags。参数与图哈希见 `int8_head_excluded_config.json`;
QDQ 零点与 scale 检查见 `int8_qdq_audit.json`。

校准使用 CPUExecutionProvider,并仅在当前进程限制 ORT 线程数,不改写安装包。
图仅先补充 ONNX shape/type 信息,没有更改评测模型或训练权重。原始警告保留在
`int8_full_quantize.log`;其中 rank-1 参数无法按默认 axis 做逐通道量化的警告,
不等于所有参数均逐通道量化,实际 QDQ 结构以 audit 为准。

**全量 QDQ 崩塌已定位到输出表示。** 标签寻址与预处理均已核验正确;
四张真实图在 ORT QDQ 和 TensorRT QDQ 中类别分数全部为 0。图追踪显示最终输出把像素坐标
与概率拼在同一个张量后,以同一个对称 INT8 scale 量化,0–1 的概率都落入零的舍入区间。
该输出量化足以解释零类别分数;**这不证明其余中间层量化完全无损。**

全量 QDQ 结果及诊断全部保留;输出头排除是一次明确登记的后续实验,未反复搜索到"好看"为止。
节点清单保留在实验机工作目录，未随仓库发布;
被排除的是检测头输出与后处理相关的节点,清单保存在同一文件中(报告不再逐条列出)。

全量失败档的类别翻转数最多,但那是**所有类别分数归零后 argmax 平局**造成的,

## 7. 背景图虚警

统计 conf>0.25、类别感知 NMS IoU=0.7、max_det=300 的误检框。
样本含评测集与校准集中的空白标注图,因此区分统计口径,避免把含校准样本的统计当成独立测试。
来源:`background_summary.json`。

结论:把输入从 1024 换成带灰边的尺寸后,背景图上的误检框数几乎翻倍(评测子集同样翻倍);
INT8 最终候选的误检数最低;全量失败档的零虚警来自失效,没有部署意义。
